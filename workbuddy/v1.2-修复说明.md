## 三、关键修复的细节（便于其他 AI 直接对照当前代码核对）

### R03 信用卡负债符号（最高优先，会计 bug）
- **问题**：旧指南里"支出就减余额"对信用卡（负债账户）也成立，导致刷卡消费后净资产凭空增加。复现：储蓄 1000、信用欠款 0，刷卡 100 → 净资产被算成 1100（应为 900）。
- **修复**：新增 `signedBalanceDelta(account.Category, signedAmount)`：
  - 资产账户（category 1–9）：支出使余额减、收入使余额加；
  - 负债账户（category 10–15）：消费使余额**增**（欠更多）、还款使余额**减**（还掉一部分）。
- **验证**：储蓄 1000 + 信用欠款 0，刷卡 100 → 储蓄 900 + 信用欠款 100，净资产 = 900−100 = **900** ✅（不再虚增）。

### R05 WebSocket 授权与可见性（隐私）
- **问题**：旧 `ServeWS` 信任客户端 `subscribe` 报文里的 `books`，任何人拿到 token 即可订阅任意账本并拿全量交易，击穿"隐私优先"卖点；且广播未做可见性过滤。
- **修复**：
  - 连接建立即绑定认证 `uid`（来自 `JWTAuth` 上下文）；
  - `Hub.Subscribe(uid, bookID)`：受锁更新 `clients`，并对**每个** `bookID` 调 `services.CanSubscribe(uid, bookID)` 服务端校验成员资格，非成员静默忽略；
  - 广播 `BroadcastToBook(bookID, uid, payload, opts)`：先 `services.CanViewDetail`，关闭互看时只发脱敏通知（不含金额/账户/备注）。

### R01/R02/R06 把 v1.1 正确实现同步回骨架
- 旧 `AddTransaction`：先 `Get` 账户、内存加减、再 `Update`——非原子、并发丢更新、吞错误、无版本号。
- 新写：单条 `UPDATE accounts SET balance=balance+? WHERE id=? AND book_id=? AND deleted=0`，检查 `RowsAffected==1`；并在同一事务内 `UPDATE book_versions SET version=version+1 WHERE book_id=?` 后回写 `tx.SyncVersion`。

### R08/R09 认证
- 移除 `var jwtSecret = []byte("改成你自己的密钥")`；
- 新增 `InitAuth(secret string)`：空密钥启动即 `log.Fatal`；
- `JWTAuth()`：限定 `SigningMethodHS256`、用类型断言安全读 `uid`、查 `users.disabled/deleted` 拒绝失效账号；预留 `jti` 吊销字段。

## 四、签名变更（提醒下游调用方需同步）

| 函数 | 旧签名 | 新签名 |
|---|---|---|
| `AddTransaction` | `(uid, tx)` | `(uid, bookID int64, tx *models.Transaction)` |
| `Transfer` | `(uid, fromId, toId, amount)` | `(uid, bookID int64, fromId, toId, amount)` |
| `JWTAuth` | `(secret string)` | `()`（密钥经 `InitAuth` 注入） |

> 这些是**设计文档/代码骨架**，不依赖真实 Go 编译；但 handler/路由层若已照旧签名写，需随之调整（仓库当前尚无真实源码，仅文档级骨架）。
