## 二、关于"两级分类"误判的复盘（给自己的约束）

原评审 3.3 我写的是"原型'两级分类/我的设置'两页需核实"——这是**模糊的"需核实"式措辞**，对方把它当成"缺页"问题来反驳，造成一轮无效往返。

根因：我搜的是中文字面标签"两级分类/我的设置"，原型里这两页用的是 `categories`/`category`/`设置` 等更通用的键，字面没命中就下了"找不到入口"的结论。正确做法应是先 grep 原型资源确认功能是否存在，再决定是否提"缺页"。

**下轮对自己的硬约束**：涉及"原型页面/功能是否存在"的论断，必须先 grep 原型 `assets/*.js` 给出命中证据；拿不准的一律标注为**开放式待确认**，不写成"缺/找不到"的肯定句。

## 三、下一轮交叉审查小提示（可原样转交对方，也可作你逐条核对的 checklist）

**核心原则**：双方都按"可定位、可验证、可追溯"的格式提问题，你再逐条核对——**属实的修，误判的说明理由，不盲目改**。

1. **每条问题必须带 3 要素**：`文件路径` + `章节号/行号` + `原文片段或截图`。
   - 例（好）："落地方案 §6.1 Lxxx：`ChangeBalance` 未显式用事务包裹，请确认并发安全。"
   - 例（差）："转账可能不安全。" ← 无法定位，易误判。

2. **区分断言与待确认**：
   - 能 grep/读源码确认的，写成肯定句并附证据；
   - 拿不准的，显式标 `[待确认]`，不要把猜测当事实。

3. **用 CHANGELOG 追踪每条状态**：每条评审意见在 CHANGELOG 里只有三种结局——`已采纳(附改动位置)` / `未采纳(附理由)` / `待确认`。避免"改了一部分"的悬空状态。

4. **跨文档一致性优先于挑刺**：新版本最该防的是"A 文档改了、B 文档没跟上"。提问题时优先查 PRD / 落地方案 / 新手指南 / 原型 四处是否口径一致。

5. **误判不可耻，但要即时收回**：像这次"两级分类"——对方反驳后，我立刻 grep 核实并认错，比硬拗省一轮。建议对方同样：被证伪的意见在 CHANGELOG 标 `误判` 并简短说明，不删不改口硬撑。

> 一句话给下一轮：**凡是"缺 X / 找不到 Y / 不一致"这类结论，先给文件路径+行号+证据，再下笔。** 这能直接消灭上一轮那种"误判式往返"。
