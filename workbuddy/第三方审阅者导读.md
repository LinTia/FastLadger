## 1. 项目是什么（一句话）

**FastLedger** = 一款**自托管**（部署在家庭 NAS / Docker）的**家庭智能记账与资产管理系统**。

- **核心闭环**：付款截图 → 端侧 OCR + 规则解析 → 人工确认预填 → 入账 → 家庭实时共享。
- **差异化卖点**：数据完全在自己手里、隐私优先（图片不上传，识别默认端侧完成）。
- **技术栈（规划）**：后端 Go + Gin + xorm + SQLite（预留 PG/MySQL）；客户端 Flutter（Win/Android/iOS）；Web 由后端 `go:embed` 托管；部署 Docker + Caddy 反代 + 自动 HTTPS。
- 详细定义见仓库根 [`README.md`](../../README.md) 与 `docs/` 下各文档。

## 4. 本项目的审阅约定（请务必遵守）

这是项目方与前面 AI 约定好的协作规范，照做能大幅减少无效往返：

1. **每条问题必须带 3 要素**：`文件路径` + `章节号/行号` + `原文片段或截图`。
   - ✅ 好："落地方案 §6.1 Lxxx：`ChangeBalance` 未显式用事务包裹，请确认并发安全。"
   - ❌ 差："转账可能不安全。"
2. **区分"断言"与"待确认"**：能 grep 源码/原型确认的，写肯定句并附证据；拿不准的，显式标 `[待确认]`，**不要写成"缺 / 找不到"的肯定句**（前一轮就因搜中文字面没命中就下"缺页"结论，造成误判）。
3. **用 CHANGELOG 追踪每条状态**：每条意见只有三种结局——`已采纳(附改动位置)` / `未采纳(附理由)` / `待确认`，不留悬空。
4. **跨文档一致性优先**：新版本最该防的是"A 文档改了、B 文档没跟上"，提问题优先查 PRD / 落地方案 / 新手指南 / 原型 四处口径是否一致。
5. **误判即时收回**：被证伪的意见在 CHANGELOG 标 `误判` 并简短说明，不硬撑。
6. **总体原则**（项目方原话）：**属实的修，误判的说理由，不盲目改。**

## 5. 已经确定的设计决策（除非有新证据，勿轻易推翻）

这些在 v1.1 已经定稿并落到文档/代码级，推翻需给出更强的新理由：

- **MVP 即支持多账本**：默认"家庭公共账本"，可新建"个人私账"并切换（统一了早期 PRD 写"单账本"的矛盾）。
- **增量同步机制**：账本级 `book_versions` 全局版本号 + 实体 `sync_version`，**写事务内原子 +1 并回写**；`sync/pull` 按 `afterVersion` 拉取。覆盖增/改/删。
- **隐私定位**：图片不上传；云端大模型仅作**可选兜底**且只传文本；原型零外部请求、可完全离线（已删除早期残留的字节系遥测脚本）。
- **并发冲突**：服务端权威 + 版本号，冲突返回 409，用户"覆盖 / 放弃 / 另存副本"三选一（家庭场景概率极低，不做 CRDT）。
- **金额用整数分存储**；SQLite 连接开 `WAL` / `busy_timeout` / `foreign_keys`；`ChangeBalance` 为单条原子 `UPDATE`。
- **录入耗时两口径**：OCR 响应 **< 3 秒**（设计目标，不含人工）；完整一笔 **≤ 15 秒**（验收阈值）。
- **自托管场景取舍**：`email` 改为可选（常无 SMTP）；移除 `transactions.geo_lng/geo_lat`（不再采 GPS）；`users` 表仅留 `password_hash`（bcrypt 内含盐，删独立 `salt` 列）。

## 6. 给新审阅者的上手建议（怎么下手最高效）

1. **阅读顺序**：`README.md` → `CHANGELOG.md` → `workbuddy/` 两份评审 → `docs/` 四份文档 → 跑一遍 `prototype/`。
2. **动手前提**：先确认你的意见没在 CHANGELOG / 两份评审里出现过。
3. **关于原型**：`prototype/` 是某原型工具导出的**构建产物快照，仓库内无可编辑源码**（已在 `prototype/README.md` 注明）。如需改交互，请注明"需回原型工具改"，不要要求仓库提供源码。
4. **提意见格式**：按第 4 节，最好直接给"建议改动位置 + 理由 + 影响面"。
5. **欢迎新方向**：全新改进（新功能、新权衡、新风险识别）非常欢迎，但请说明它和上面第 5 节已定决策的关系，避免和既定方案打架。
6. **落地方式**：文档改动建议直接给"改后文本 + 位置"，方便项目方或协作者采纳并写进 CHANGELOG。
