## 2. 各项改动明细

### GPT-R04 幂等（已修复）
- 新增表 `idempotency_records`（指南 §6.4）：`UNIQUE(book_id, uid, client_uuid)`，含 `request_hash`（请求摘要）、`result_type`、`result_ids`。
- 重写 `AddTransaction`（指南 §13.1）：在事务内先查回执 → 内容相同直接返回（不产生第二笔）、内容不同报冲突；不存在则先占位，唯一索引兜底并发竞态；业务完成后回写 `result_ids`。
- 转账不使用"两侧共用 UUID 加全局唯一索引"，统一由回执表处理（result_type=2，result_ids 存两条）。
- 新增 `requestHash(tx)`（SHA-256 摘要）。

### GPT-R07 游标/快照（已修复）
- 指南 §22 概述：WS 事件只表示"有新版本"，**不直接推进已同步游标**；游标仅在完整应用一个 pull 批次后推进到 `highVersion`。
- 重写 §22.2：`Pull` 在**同一个只读事务（一致快照）**内先确定水位 `highVersion`，再读取交易/账户/分类/持仓；新增 `SyncBatch` 结构。
- 明确分页不得拆分同一 `sync_version` 的变更组；缓冲溢出要求全量重同步。
- 落地方案 §5.2 同步该语义。

### GPT-R10 恢复世代（已修复）
- 新增"恢复世代" `restore_epoch`（指南 §26.1）：独立于数据库、不随备份恢复的 `data/instance.meta`。
- 每次 restore 递增 `restore_epoch`；登录/握手/health 返回该值。
- 客户端发现世代不符：停止旧游标增量同步 → 全量重建本地库 → 离线队列逐条核对重放。
- 落地方案 §8.3 恢复步骤已加入递增世代。

### GPT-R11 非法输入/持仓（已修复）
- 指南 §13.1（v1.2 已含金额正值、类型白名单校验）。
- 重写 `AddHolding`（指南 §16.1）：`decimal.NewFromString` 的错误**必须返回**（不再丢弃），校验数量/价格非负；在事务内校验投资账户（category=5）与标的归属同一账本，接入版本号。
- `holdings` 表补 `book_id`、`sync_version`、`deleted`（软删除墓碑）。

### GPT-R12 契约统一（已修复）
- 字段统一：指南 §6.4 用 `password_hash`、`members_can_view_others`；§9.3 User 模型显式列映射 `PasswordHash → password_hash` 并补 `Disabled`；§10.1 同步。
- WS 契约统一（指南 §7.4 与落地方案 §5.2）：路径 `/api/v1/ws`、订阅 `{"action":"subscribe","books":[...]}`、事件名点号风格（`transaction.created/updated/deleted`）、事件均带 `version`。

### GPT-R13 预算（已修复）
- 重写 §18.1：按 `budget_type` 分支——分类预算收集"大类 + 所有小类 ID"（IN 查询，未来改递归）；总预算去掉分类谓词。
- 周期用账本市时区下的半开区间 `[start,end)`。
- 聚合改用 xorm 正确 API `SumInt`（替代有签名问题的 `SQL().Scan`）。

### GPT-R14 CSV 注入（已修复）
- 新增 `sanitizeCSVCell`（指南 §17.1）：用户可控文本（分类名/账户名/备注）首字符为 `= + - @ \t \r` 时前置单引号。
- 区分"给表格软件的安全 CSV"与"给程序消费的原始 JSON"；BOM 不等于公式防护。

### GPT-R15 OCR 千分位（已修复）
- 重写 §21.5：金额正则支持千分位 `[0-9]{1,3}(,[0-9]{3})*(\.[0-9]{1,2})?`；先做全角→半角规范化；`_toCents` 用整数方式转分（不用 double）。
- 补测试样例：普通/千分位/一位小数/退款负数/多金额/异常分组（异常回退人工）。

### GPT-R16 PRAGMA / 编译错误（已修复）
- 重写 §22.4：PRAGMA 改用 go-sqlite3 **DSN 参数**（`_journal_mode/_busy_timeout/_foreign_keys/_synchronous`），对连接池每个连接生效；`SetMaxOpenConns(1)`（MVP 最稳，多读扩展另建只读引擎）；启动后 `PRAGMA foreign_keys` 校验并对不生效报错。
- 修正 §22.2 `Find(&[]T{})` 等错误用法、§18.1 聚合 API。

### GPT-R17 MVP 范围（已修复）
- 统一为 PRD 基线：v0.1 含**基础报表（月度收支、分类占比）+ CSV/JSON 导出**。
- 落地方案 §1.4 后置表改为"高级图表/自定义报表""完整预算"，MVP 功能列表补基础报表与导出；§8.6 版本路线同步。
- 指南 §27 版本路线同步，后端任务新增 9.1。

### GPT-R18 WS 并发（已修复）
- 订阅 map 所有写经 `Hub`（固定锁顺序 `Hub.mu → Client.mu`，禁止反向）。
- 读写循环共用取消上下文，`Unregister`/`Close` 在主 defer 恰好清理一次；读 goroutine 只 `cancel`。
- 明确 `Send` 通道**永不关闭**（避免向已关闭 channel 发送 panic），靠 Unregister 回收。
- 写循环加 30s ping；客户端周期 pull 兜底通知丢失。建议用 `go test -race` 验证。
