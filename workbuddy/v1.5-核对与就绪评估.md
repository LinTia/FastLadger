# v1.5 核对与“能否开发”评估（WorkBuddy 复核）

核对基线：`f057919`（CHANGELOG 记为 `[1.5]`）。本文件是对 `gpt/v1.4/` 审核与裁决的第三方复核，以及“文档是否已到可开发状态”的判断。

## 1. 核对的不是纸面，GPT 真跑了代码

`gpt/v1.4/verification/runtime-results.json` 是真实产物，不是总结：
- 工具链：Go 1.27.3、xorm v1.4.3、go-sqlite3 v1.14.52、shopspring/decimal v1.6.0；`go test -race` 覆盖交易函数与 Hub 核心。
- 旧片段反例 **30 项全 pass**（exit_code 0），其中明确复现了：R03 还款净资产 90000→70000、R06 账户版本 0、R20 改分类/渠道仍同 hash、R19 空回执却提交 2 条交易、R23 `AddTransaction(txType=3)` 只插 1 条且两侧余额不变、R16 旧初始化 3 处编译错误。
- 修订骨架回归（统一 `Create`）**全 pass**，含 4 种资产/负债方向净资产守恒。
- 旧初始化编译包确实 fail，报出 DB 返回值、Engine.QueryRow、外包接收者 3 个真实错误——证明 R16 非虚报。
- 诚实边界：Hub 权限用桩、无真实 HTTP/WS 生命周期、无 Flutter、无端到端；这些 GPT 在 `runtime-results.json.limitations` 与审核结果 §状态说明 明确标注，未冒充“全应用通过”。

结论：**GPT-R19~R23 与 R03/R06/R16 的复现与修复均属实，无虚报、无误判，且修复经真实编译/运行验证。**

## 3. 是否已“能开发”——分层结论

| 层 | 状态 | 说明 |
|---|---|---|
| 交易核心设计（幂等/版本/双边原子/净资产守恒） | ✅ 已就绪且经运行验证 | 这是最容易写错、最致命的部分，现已证明正确 |
| 跨文档一致性（PRD/方案/指南/裁决） | ✅ 一致 | 入口、回执、余额方向口径统一 |
| 实际后端源码 | ❌ 不存在 | 仓库内无任何 `*.go` 业务文件（仅 GPT 沙箱与预编译原型）；开发者需从骨架新建工程 |
| Gin Handler 接线 | ⚠️ 未验收 | R21 服务层已强制，但 400/409 映射、路由、JWT 注入未实现 |
| 真实 WebSocket 生命周期 | ⚠️ 未验收 | Hub 仅核心 race 测过，成员移除/可见性变化/真实读写未做 |
| Flutter 源码 | ❌ 不存在 | `prototype/` 仅是预编译 web 产物，无法二次构建/改 |
| OCR（核心卖点）后端契约 | ⚠️ 薄弱 | 原型有 UI，服务端识别→结构化→确认链路未在骨架细化 |
| 统计/导出（R05） | ⚠️ 部分 | API 表有，但实现未细化 |
| 转账删除/恢复、迁移、端到端 | ❌ 未做 | 裁决明确“不宣称已实现” |

**一句话：架构/设计已到“可据此开工”的水平（钱正确性引擎被验证过），但仓库不是“clone 即跑”的可运行项目，而是“照骨架实现”的 green-field 工程。** 把“能开发”理解为“能开始写代码”=是；理解为“能部署运行”=否。

## 4. 启动开发前建议补齐（优先级）

1. **P0 脚手架**：初始化 Go module、目录（`internal/services`、`internal/ws`、`internal/repo`、`cmd/server`）、xorm 引擎与 DSN 初始化（用已验证的 §22.4 版本）。
2. **P0 落地统一 Create**：把指南 §13.1 抽成真实文件并接 Gin 路由，完成 R21 的 400/409 接线与 `clientUuid` 校验。
3. **P0 数据库迁移**：`idempotency_records` 新表 + `result_version` 字段；写迁移脚本（含老库升级，裁决警告“不得删旧回执”）。
4. **P1 WebSocket**：把 Hub 桩换成真实鉴权/会话，实现成员移除与可见性失效推送。
5. **P1 OCR 契约**：定义截图→识别→结构化→3 秒确认的后端接口与错误回退（核心卖点，当前最薄弱）。
6. **P2 统计/导出、转账删除恢复、Flutter 从原型重建源码**。
