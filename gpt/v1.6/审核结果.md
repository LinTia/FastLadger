### 6. problem
Go 的 `go test` 对没有测试文件的包仍可能返回成功，并显示 `[no test files]`。当前 CI 命令没有触发任何测试函数，因此不能证明 `mattn/go-sqlite3` 已成功打开真实 SQLite 数据库，也没有调用 `database.Init`、读取 PRAGMA 或执行 `migrate.Apply`。步骤名称“证明不是 stub”与实际执行内容不符。

### 7. reproduce
1. 打开 GitHub Actions run `41010979053`。
2. 查看步骤“SQLite 驱动冒烟（证明不是 stub）”。
3. 日志显示 `internal/migrate` 与 `internal/database` 均为 `[no test files]`。
4. 核对当前 main 仓库树，这两个目录均没有 `*_test.go`。
5. 因而该命令没有运行 SQLite 冒烟断言。

### 8. actual
CI 步骤显示成功，但两个目标包均没有测试文件；实际只完成包编译/测试框架扫描，没有运行 SQLite 测试逻辑。

### 9. expected
CI 应执行至少一个真实测试用例，并在用例内：
- 通过 `database.Init` 创建临时 SQLite 数据库，确认驱动确实可用；
- 读取并断言 `foreign_keys=1`、`journal_mode=wal`、`synchronous=2`；
- 执行 `migrate.Apply` 并核对 schema 版本；
- 再次执行迁移，验证重复执行不会重复应用；
- 对临时数据库进行可靠清理。

若测试包意外没有测试文件，CI 应明确失败，而不是以成功状态通过冒烟门禁。

### 10. impact
当前 CI 可能在数据库驱动不可用、PRAGMA 配置错误或迁移执行失败的情况下仍通过这个专门的冒烟步骤。由于该步骤被 CHANGELOG 用作“真库验证已完成”的证据，会造成验证覆盖范围被高估。全量 `go test ./... -count=1 -v` 与 race detector 的成功记录仍然有效，但不能替代这项明确的 database/migrate 集成验证，除非能提供覆盖相同行为的具体测试用例和日志。

### 11. suggestion
1. 新增 `server/internal/database/database_test.go`：使用临时目录调用 `Init`，断言 SQLite 连接可用及三项 PRAGMA 值。
2. 新增 `server/internal/migrate/migrate_test.go`：在临时数据库上执行迁移，核对版本及重复执行行为。
3. 保留现有 CI 命令；测试文件提交后，确保日志显示实际 `ok` 与测试用例执行，而非 `[no test files]`。
4. 可以增加一个轻量门禁，检查这两个包至少存在一个测试文件，防止未来测试被删除后冒烟步骤静默空转。
5. 回填 CHANGELOG 时区分“全量 Go 测试通过”和“数据库初始化/迁移真实集成测试通过”，并为后者附具体测试名称与运行证据。
