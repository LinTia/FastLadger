## 2.2 B4：窄屏表格隐藏规则影响面与候选 CSS

**判定：部分通过；不得应用任何候选补丁。**

通过项：

1. B4 正确识别 `style.css:331` 的裸全局选择器会影响多个页面。
2. 9 张表的枚举比此前清单完整，覆盖交易、账户、回收站、分类排行、持仓两张、标的库、API Token、成员表。
3. B4 修正了此前把 `app.js:1614` 误称为“备注模板表”的问题；该处实际是 API Token 列表。
4. 候选 A 不再使用旧的 `table:has(th:nth-child(5))`，而是用 8 列表头定位交易表，再只在该表保留原有第 1、5 列隐藏行为。静态看，这比旧方案准确，能避免把其他表继续按列位置隐藏。
5. B4 明确承认恢复其他表列后可能发生横向溢出，并要求运行时回归；没有宣称 CSS 已修复。

必须修订/补证：

1. **“T1 符合设计意图”证据不足。** 当前代码只证明交易表第 1 列是复选框、第 5 列是分类；不能仅凭现状证明产品已决定这两列应在窄屏隐藏。请改成“候选 A 暂时保留交易表当前裁剪行为”，不要把现状推断为已确认设计意图。
2. 候选 A 会恢复 T2–T9 的第 1、5 列。对于 6/7 列持仓、回收站等表格，B4 自己也指出没有表格级横向滚动容器；所以“列恢复”不等于“窄屏可用”。**必须先实测，不得仅凭 CSS 选择器推导通过。**
3. `document.documentElement.scrollWidth <= document.documentElement.clientWidth` 不能单独证明每张表都没有溢出或被裁切。验收应增加逐表测量：表格与容器的 `scrollWidth/clientWidth`、`getBoundingClientRect()`、实际横向滚动可达性，以及关键单元格是否可见。
4. T6（标的库）编辑/删除与 T7（API Token）撤销的按钮回归，应明确只测试“打开弹窗/确认框后取消”，不得实际删除标的或撤销 Token。验收步骤应写明非破坏性测试。
5. B4 的授权范围已经从原先“仅账户名称”扩大为 8 张受损表的影响修复。原 OBS-ACCT-VIS-390 记录不能自动扩展为 8 表授权；必须由 Owner 明确确认范围。B6 也应同步写明这个范围变更。

建议保留候选 A 为“待运行验证的临时候选”，不批准直接应用。候选 C 涉及 `app.js`，必须另行授权，不能借 OBS 授权顺带实施。
