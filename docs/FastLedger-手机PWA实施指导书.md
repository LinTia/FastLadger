# FastLedger 手机 PWA 实施指导书

> 文档性质：面向后续 AI / 开发者的实施决策与任务指导书，用于指导修订 PRD、落地方案、开发 WBS 并拆分实施任务；不是代码已完成报告。
>
> Owner 已明确的产品方向：**完整移动端 + 完整离线 + 离线数据备份与恢复**。本文中的技术建议须先经项目文档对齐；未实测的能力不得标为已交付。

## 1. 目标与边界

FastLedger 增加可安装的手机 PWA，面向 Android / iOS 手机浏览器：

- 在线提供完整移动端记账体验；离线可查看已缓存数据、录入允许离线操作的账目、进行本地账单分析。
- 离线操作持久化排队，联网后遵循既有同步契约补传；不得重复记账、静默覆盖冲突或复活已删除数据。
- 支持离线导出本机备份，并在本机校验、恢复。
- 复用现有 Go API、权限、账本版本、clientUuid 幂等、软删除、审计与 restore_epoch 契约。

边界：
- PWA 不替代 Flutter Windows / Android / iOS 原生客户端；全局截图、Windows 热键、Android 悬浮球等仍由原生端承担。
- 不承诺 iOS Safari 后台持续同步、后台定时任务、跨 App 全局截图或悬浮球。
- 首次安装和首次缓存需要在线；浏览器清理站点数据、系统回收存储或卸载可能丢失本地数据，必须提示用户定期导出备份。
- 离线报表只代表本机已缓存数据，不得把“本地没有”解释为“服务端不存在”。
- PWA 用户级备份不等于服务端整库备份；整库备份仍仅限实例管理员。

## 2. 仓库现状与技术路线

### 2.1 已核对的现状

- client/ 是现有 Flutter 工程，包含 Android / Windows；client/web/ 已有 Flutter Web manifest 和图标，但这不等于 PWA 已完成。
- client/lib/core/local_store.dart 当前只有 LocalStore 抽象与 InMemoryLocalStore；注释说明结构化数据持久化仍待接入。
- client/lib/queue/outbox.dart 将队列序列化到 LocalStore；当前 4xx 会被丢弃。PWA 不可直接照搬这一规则，冲突、ENTITY_DELETED、403 等必须保留用户可见的处置路径。
- server/web/dist/ 是 Go embed 的现有 Web 静态资源；server/internal/api/web_handler.go 将其托管在根路径。代码注释说明当前 Web 端为手写 HTML/JS/CSS，无 npm 构建链。
- 后端已有 REST、WebSocket、sync/pull、sync/push、账本版本与 restore_epoch 基础能力。

### 2.2 推荐方案

**建议在现有 server/web/dist Web 客户端上演进移动优先 PWA，由 Go 单二进制继续内嵌托管；Flutter 原生端并行保留。**

理由：复用现有部署入口与 API；无需增加 Node 服务/容器；PWA 无法替代原生截图能力；当前 Flutter 本地存储尚非生产级结构化持久层，不能仅因 manifest 存在就把 Flutter Web 当成完整离线 PWA。

不建议未经 PoC 就把 Flutter Web 定为唯一 PWA 路线。若要评估 Flutter Web，须单独验证 IndexedDB / SQLite WASM、插件兼容、首屏体积、iOS Safari 存储和 Service Worker 更新，并以真机结果重新裁决。

### 2.3 目标架构

手机浏览器 / 已安装 PWA：
- Mobile UI：响应式、触控优先、安全区适配。
- App Shell：HTML/CSS/JS、图标、字体、路由。
- Service Worker：只缓存版本化静态资源与离线导航 fallback；不缓存鉴权 API、私人响应、备份文件。
- IndexedDB：业务数据、outbox、冲突箱、同步游标、restore_epoch、分析缓存。
- WebCrypto：本地备份加密与解密。
- Sync Engine：在线 push → pull；WS 只作为变更提示；冲突显式处理；权限/世代变化时清理并全量重建。

通过 HTTPS REST + WebSocket 连接现有 Go API 与 SQLite，不另造同步协议。

### 2.4 本地存储

- IndexedDB 是 PWA 权威本地持久层；封装独立 PwaLocalDatabase / repository，不允许页面直接散落数据库操作。
- 选型轻量、支持事务、维护活跃的 IndexedDB 封装库；具体依赖版本须核对许可证、维护状态、安全公告和 iOS Safari 兼容后登记，不要把 localStorage 当交易数据库。
- IndexedDB schema 必须版本化迁移；迁移失败不得清空数据，应停止写入并提示导出/升级/恢复。
- 金额统一整数分；禁止 JS 浮点累加。使用安全整数分或 BigInt，并明确 JSON 序列化转换。
- Token 不进入业务备份。优先评估 Secure Cookie + CSRF；若沿用 Bearer Token，必须记录 XSS 风险与生命周期策略，PAT 明文不得持久化到 IndexedDB 或备份。
- 仅缓存当前用户有权访问的数据；换用户、退出登录、成员移除、权限收紧必须执行数据隔离与清理。

## 3. 离线功能要求

| 能力 | 在线 | 离线 | 约束 |
|---|---|---|---|
| 登录/注册 | 支持 | 不支持 | 仅已登录且有本地缓存身份的用户可进入离线工作区；离线不注册、不刷新凭证 |
| 账本切换 | 支持 | 已缓存账本 | 标注上次同步时间与离线权限状态 |
| 交易列表/搜索/筛选 | 支持 | 已缓存数据 | 不得伪装为服务端全量数据 |
| 新增交易 | 支持 | 支持 | 本地事务写业务记录 + outbox，生成稳定 clientUuid |
| 编辑/删除 | 支持范围内 | 有条件 | 必须以服务端已开放 API 为准；不得本地假成功 |
| 转账 | 支持 | 支持 | 一笔业务命令，复用服务端唯一 Create、双边原子与幂等契约 |
| 基础报表/账单分析 | 支持 | 支持 | 只基于本地缓存，展示覆盖范围与最后同步时间 |
| 账户/分类/成员管理 | 支持 | 默认只读 | 只有明确列入离线白名单的操作才允许排队 |
| CSV/JSON 导出 | 支持 | 支持 | 离线导出当前设备持有的数据并标明范围 |
| 本地备份/恢复 | 支持 | 支持 | 不依赖服务器 |
| 服务端整库备份 | 按权限 | 不支持 | 仅实例管理员 |
| OCR/截图 | 受浏览器限制 | 受浏览器限制 | 可评估用户主动选图后本地 OCR；不承诺跨 App 截图 |

### 3.1 离线账单分析

首期至少支持本月收入/支出/结余、日/月趋势、分类占比、账户汇总、关键词与时间筛选。高级分析（商户排行、同比环比、预算执行）后置。

分析必须从 IndexedDB 计算或读取本地分析缓存；断网时不能调用 API 后把空响应当作零。页面展示：
- 本地数据截至时间；
- 已缓存记录数量；
- “离线结果仅基于本设备已同步数据，可能缺少其他设备尚未同步的记录”提示。

金额按整数分聚合。若历史数据不完整，必须标注“基于已缓存数据”，不得展示虚假的完整账本结论。

### 3.2 同步与 Outbox 规则

1. 同一 IndexedDB transaction 内写本地业务记录（pending）和 outbox 项，生成一次且仅一次 clientUuid。
2. 联网顺序遵循项目既定 push 本地队列，再 pull 服务端增量；成功回执与本地操作关联。
3. 网络错误/5xx 保留队列并退避重试；2xx 按回执更新本地记录并出队。
4. 409 冲突、ENTITY_DELETED、403、校验类 4xx 不得静默丢弃；进入冲突/失败箱，展示原因和允许的动作。
5. 相同 clientUuid 重试必须重放完全相同命令；修改内容须生成新操作键。
6. 同步游标以 book_versions 为准，不得以本地时间戳代替。
7. WebSocket 仅作变更提示；断线重连仍须 pull 补齐。
8. 检测 restore_epoch 变化时暂停 push，隔离旧缓存/队列，先全量重建并逐项核对；不得让恢复前的旧离线数据覆盖恢复后的服务端状态。
9. 成员移除、可见性变化时，按既有事件契约清理受影响账本缓存；不得从旧备份自动恢复并同步已失权数据。

### 3.3 离线 UX

顶部常驻在线/离线/同步中/有冲突/上次同步状态。pending 交易明确显示“仅保存在此设备，待同步”。失败队列可查看详情和重试。离线登录不绕过服务端鉴权：无法联网验证时提示身份状态待确认，并限制敏感管理操作。

## 4. 本地备份与恢复

### 4.1 备份内容

定义独立、版本化归档格式（建议带 manifest），至少包括格式版本、导出时间、应用/数据 schema 版本、账本 ID、记录条数、校验信息，以及当前用户有权访问的业务数据和同步水位。

outbox / 冲突箱默认单独选项；恢复时必须二次确认。不得包含 JWT、PAT 明文、服务端密钥、无权访问的数据、Service Worker 缓存。

### 4.2 加密与校验

建议默认加密：WebCrypto AES-GCM，使用 PBKDF2 从用户口令派生密钥；每份归档随机 salt 和 IV，禁止复用 IV。算法、参数、格式版本写入 manifest。解密后校验认证标签、结构、条数与完整性；任何校验失败都不得覆盖现有数据。口令丢失无法恢复，界面必须明示。

导入采用 staging：先解析到临时存储并完整校验，再切换正式数据；多 object store 无法单事务原子切换时，使用 commit marker 和启动恢复检查。

### 4.3 恢复语义

- 默认“仅恢复到本机”：覆盖/合并前先备份当前本地数据；绝不自动向服务端 push。
- “恢复后与服务器合并”作为高级显式操作：联网重新认证、确认目标用户和账本权限，逐项按版本与幂等规则处理；旧 outbox 默认隔离，不自动重放；冲突进入冲突箱。

严禁导入后自动全量 push，避免重复交易、覆盖新数据、复活删除实体或回流已失权数据。

### 4.4 与服务端备份的关系

PWA 用户级备份与服务端每日整库备份是两条独立保护链。服务端继续使用现有 online backup 机制、7 份滚动保留与恢复演练；PWA 不下载 SQLite 文件。整库备份仍仅实例管理员可用。

## 5. 安全与浏览器限制

- 全站 HTTPS；Service Worker 仅在安全上下文注册。
- SW 仅缓存静态 App Shell 与版本化资源；严禁缓存 /api/*、/ws、用户数据响应、Token、备份文件和错误响应。API 必须 network-only。
- XSS 是高风险面：禁止不可信 HTML 注入，用户输入按文本渲染；评估严格 CSP，兼容现有内嵌资源。
- IndexedDB 不是加密保险箱；设备失窃、同设备其他用户、恶意扩展均有风险，不得宣称等同 Keychain/Keystore。
- 可请求 navigator.storage.persist()，但不得视为保证；显示存储用量并提醒导出备份。
- Android Chrome 与 iOS Safari 的安装、更新、存储配额、文件下载/导入、后台恢复必须真机验收。

## 6. 后端契约

首期原则上不新增业务 API、不改数据库 schema，复用现有登录、账本、账户、分类、交易、sync/pull、sync/push、clientUuid 幂等、WS、restore_epoch、权限、软删除和审计。

若发现必须新增 API（例如安全 Cookie、离线批量快照、用户级备份清单），必须先给出 API 契约、鉴权、权限、幂等、限流、审计和兼容方案，再同步 PRD / 落地方案 / WBS；不得先写前端 mock 再倒逼后端。

7. 文档冲突先列证据与影响，再按优先级修订；禁止在代码中自行选边。

**结论**：手机 PWA 可行。推荐基于现有 Go 托管 Web 客户端增加移动优先 UI、Service Worker 与 IndexedDB 离线数据层。完整离线的关键不是缓存页面，而是本地业务数据库、可恢复 Outbox、遵守服务端版本/权限/恢复世代契约的同步引擎，以及经过加密和校验的用户级备份恢复流程。
