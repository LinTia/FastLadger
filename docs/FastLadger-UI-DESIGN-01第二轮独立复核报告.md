## 3. P1：RV-04 残余歧义——“账户余额合计”仍被列为首页必须保留能力

### 证据

- PRD §4.2 明确首页展示本月支出、本月收入、结余；结余 = 当前账本本月收入 − 本月支出，转账不计入。
- 盘点报告 §4.3 已正确写明不得用账户余额合计或投资净资产替代首页结余。
- 但盘点报告 §6“不可删除功能清单”首页行仍写：  
  “本月收入/支出；**账户余额合计**；按日期分组账单流……”
- §6 的定义是“改造后任一项消失或降级，即视为该页验收 FAIL”，所以这不是单纯的现状描述，而是明确的未来保留要求。

### 风险

后续 UI-DESIGN-04 实施方可能因此把“账户余额合计”继续作为首页必须展示的摘要指标，甚至与“结余”并列或混淆。Owner 已确认的首页口径并未要求保留这个额外指标。

### 修订要求

将 §6 首页行改为：
- 必须保留：本月收入、本月支出、按日期分组账单流、每日小计、交易详情入口、记一笔入口；
- 首页“结余”必须按 §4.3 的 Owner 公式实现；
- “账户余额合计”只作为当前实现现状记录，不列为必须保留的首页指标。若未来确需作为独立指标展示，须另行提出，不得替代或混淆“结余”。

同时检查 §3.3 与 §5 差异矩阵，确保“当前实现事实”与“改造后必须保留要求”分开表达。

## 4. P2：RV-10 残余——待 Owner 确认事项数量不一致

### 证据

- §9.2 标题写“仍需 Owner 确认（2 项）”：桌面 5 项具体名称、低频入口分组。
- §11.6 第 3 项又把“账本设置承载页归属形态”列为“Owner + 设计”待决事项。
- §4.7 第 9 行也说账本设置承载页形态需设计归属决策。

### 修订要求

统一 §9.2 与 §11.6：
- 将账本设置承载页归属形态纳入同一待决清单，或明确它是设计执行层待定、并非 Owner 产品决策；
- 统一待确认项数量、责任人和证据位置；
- 不得重新把 D-3 / D-6 已定事项列为待裁决。
