## 0. 阅读须知：本报告能证明什么、不能证明什么

**能证明**：当前实现有哪些页面/路由/组件/样式入口；哪些功能存在且不得因视觉改造而丢失；每页依赖哪些 API 与权限；当前布局与新规范的逐条差异在哪里。

**不能证明**：不证明新规范已实施；不证明任何页面已符合新规范；不证明视觉改造后功能不回退（那是 UI-DESIGN-04/05/06 的验收范围）。

**⚠️ 关键门禁提示（必须由 Owner 明确）**：
《视觉设计规范》§9「禁止」与 §10「最终定位」、以及《开发WBS》附录 B「关键限制」均写明：**"在 R0 放行门禁未通过前，只允许进行设计基线和任务准备"**。因此 **UI-DESIGN-02 及其之后的代码改造，严格按现有文档口径是被 R0 门禁阻塞的**。
本报告只做到"盘点 + 任务拆分"，第 7 节的 UI-DESIGN-02~08 是**待授权的执行计划**，不是已获准开工的排期。

**⚠️ 基线差异提示（影响"现状"可复现性）**：
本报告描述的是 `4318fd6`（PR #3 分支）的前端状态。**`origin/main` 上缺少 4 处缺陷修复**，因此在 main 上：

**架构事实**：前端无独立进程、无 npm、无打包器；单二进制同时提供 `/`（前端）与 `/api/v1/*`（后端）。因此**任何"组件化"改造都必须在无构建工具链前提下完成**（原生 JS + CSS 自定义属性 + `<template>`/函数工厂），这是一条硬约束，直接影响 UI-DESIGN-03 的实现形态。

**安全口径现状（改造中不得破坏）**：`app.js` 全文 **0 处使用 `innerHTML`**（仅在 L2 注释中声明"禁止 innerHTML 拼接"），所有用户数据经 `textContent` 渲染。任何引入模板字符串拼 HTML 的组件化方案都会破坏这一口径，属禁止项。

### 2.5 状态设计覆盖（规范 §7 八类状态）

| 状态 | 覆盖情况 |
|---|---|
| Loading | 仅交易总表、账单流 |
| Empty | 10 处 `.empty`（账本/交易/账户/回收站/报表/预算/持仓/标的/账户详情/分类），均为"静态文案 + emoji"，无下一步入口 |

## 3. 逐页盘点（18 个视图）

> 每页按 6 个维度给出。差异等级：**A**=结构性不符（需重构布局）/ **B**=样式不符（令牌/组件替换即可）/ **C**=能力未覆盖（缺状态或入口）/ **D**=现状需保留。

### 3.1 登录 / 注册（`renderLogin`，app.js L161–231）

1. **路径/组件/样式入口**：`#view` 内单卡；`card.style.maxWidth=380px`、`margin=48px auto`（L168–169 内联）；样式入口 `.card` + 内联 cssText。
2. **与规范差异**：**B** — 无品牌区结构（emoji 📒 作 logo，L172）；卡片直角感与规范 14px 圆角/边框层级不符；无深色主题；无错误态区域（错误仅 toast）；副标题"家庭智能记账 · 截图秒记"沿用旧定位文案。
3. **不可删除功能**：用户名/密码登录；注册（用户名 + 密码 + 确认密码，`minLength=8`，L181）；注册成功自动登录（L193–199）；登录/注册互相切换（L220–228）；按钮 pending 文案（L207）。
4. **依赖**：`POST /auth/login`、`POST /auth/register`；成功后写 `localStorage.fl_token` / `fl_whoami`；401 统一清会话（L105–109）。无权限概念。
5. **手机/桌面**：手机端为唯二可达页面（另一为底栏体系），需按规范改为**移动优先单列 + 44px 触控 + 软键盘不遮挡提交**；桌面端需居中卡片 + 品牌区，不得超过 400px 宽。
6. **IA 冲突**：无。

### 3.2 账本列表（`renderBooks`，L234–303）

1. **路径/组件/样式**：`.card.book-list`（L238）；行结构 `div` 内联 flex（L257–258）；`.empty`（L243）。
2. **与规范差异**：**A** — 无页面标题栏/副标题体系（`h2` 直接在卡内）；账本行是 `a + 删除按钮` 的临时 flex 组合，非规范"卡片列表项 + 右侧操作"；无空状态下一步按钮；无加载态（`await api` 前页面空白）。
3. **不可删除功能**：账本列表（个人/家庭标识 `bookType===2`）；进入账本；**删除账本（仅 owner，服务端 403 兜底）**带确认弹窗（L262–276）；创建账本（名称 ≤40 + 个人/家庭类型，L281–301）。
4. **依赖**：`GET /books`、`POST /books`、`DELETE /books/:id`。权限：删除仅 owner。
5. **手机/桌面**：桌面端进入本页只有"点品牌名"一条路径（顶栏「账本」导航项永久隐藏），需在壳层改造时修复；手机端入口是「我的」→我的账本。D-3 要求"账本切换置顶栏"，需在冲突 2 中一并确定账本切换控件形态（下拉 vs 独立页）。
6. **IA 冲突**：见 §4 冲突 2（账本切换在桌面顶栏 / 手机抽屉的落位）。

### 3.3 首页 / 概览（`renderHome` L1963–2005 + `renderBillStream` L1906–1960）

1. **路径/组件/样式**：2 张 `.card`（标题卡 + 摘要）、`.summary` / `.summary-card`（L198–208）、`.bill-group` / `.bill-row`（L211–228）；骨架 `.skel`；`wireBottomNav`（L1893）。
2. **与规范差异**：**A + B** — ① 只有 3 张摘要卡且第三张 `accent` 用主色整块填充（L1997），规范 §5.1 要求"最多 3–4 个核心指标 + 每卡含辅助说明/比较值"，现状 `sub` 文案是硬编码（"家庭总收入"，L1995）而非真实比较值；② **指标口径不一致**：摘要"本月收入/支出"取 `reports/monthly?months=2` 末项（L1983–1984），"结余"实为账户余额求和（L1985 `balance += a.balance`）却标注为"净资产"——**未扣减负债账户，也未计入持仓市值，与投资页 `net-worth` 口径冲突**；③ 无趋势图卡、无预算/提醒次要区；④ 账单流仅取 `count=60`（L1912）无分页/无"查看全部"。
3. **不可删除功能**：本月收入/支出汇总；账户余额合计；按日期分组的账单流（今天/昨天/前天/N 天前，L1875–1890）；每日收支小计（L1933–1938）；点击行进入交易详情（L1956）；桌面「＋ 记一笔」（`.only-desktop`，L1976）；移动端 FAB。
