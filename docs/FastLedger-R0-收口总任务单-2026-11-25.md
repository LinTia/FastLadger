### 2.3 测试资产的合法修订路径与 `sourceSha256`

**事实（可复核）**：

1. `tools/r0/e2e/fixtures/controls.json:3` 存 `sourceSha256: "c9f275d44feeeaa9668e02fb6797e7f1cb76b91688e3b241cc83033dd3231316"`。
2. 该值由 `tools/r0/e2e/scripts/extract-controls.js` 生成：读取 `docs/FastLedger-R0-基准冻结与差异盘点.md` **全文**取 SHA-256（`:34` `crypto.createHash('sha256').update(raw)`），再从该文档 §3.1 的表格行解析 228 条（`EXPECT = 228`，行数不符即 `exit 1`），写入 `controls.json`（`:72–78`）。
3. 运行期由 `tools/r0/e2e/specs/c-controls.js:919` 把 `CONTROLS.sourceSha256` 写入 `controls-summary.json`，用于核对「清单版本 = 执行版本」。

**因此，`controls.json` 只有一条合法修订路径**：

```
改 docs/FastLedger-R0-基准冻结与差异盘点.md §3.1 对应行
  → node tools/r0/e2e/scripts/extract-controls.js --check   （先验 228 行结构未破）
  → node tools/r0/e2e/scripts/extract-controls.js           （重写 controls.json）
  → 校验 controls.json 新 sourceSha256 = 源文档新 SHA-256
  → 记录「旧哈希 → 新哈希」于交付回执
```

**禁止**：直接手改 `controls.json`（哈希与源文档不一致，`controls-summary.json` 将无法自证同源）；只改 `c-controls.js` 判果却声称「清单未变」（判果变了、清单没变，属测试逻辑变更，须单独授权并在回执中区分）。

**若只改 `c-controls.js` 判果、不动 `controls.json`**：`sourceSha256` 不变，但统计必然变化（当前 `164 PASS / 4 FAIL / 59 BLOCKED / 1 N/A / 228` 是按现判果得出），须同步四份文档并说明变化来源。

### 2.4 禁止的授权混用

1. **AUTH-A ≠ 业务代码授权**：AUTH-A 只能改 4 条判果，改不动一个像素的产品 UI。
2. **AUTH-A ≠ 通用 runner 改造**：59 条 BLOCKED 的配方（T09 45 条 + T10 14 条）、13 条硬编码断言、fixture 均不在 AUTH-A 内。
3. **AUTH-A ≠ AUTH-B**：两条线分别签署、分别验收、不得合并（B6 §8.2）。
4. **OD-06 ≠ 口径重开**：文档修订只做文字对齐，不得借机改「7 份」结论。
5. **测试资产授权 ≠ 统计变更许可**：统计只能按**真实复跑**结果更新，不得先改后验。
6. **Owner 交付确认 ≠ 授权**：沿用前几轮结论，会话内「推送/确认收到」不构成任何实施授权。
