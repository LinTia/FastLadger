## 1. 设计目标

FastLadger Web 不再以当前页面外观为设计基准，而是采用 HomeLedger 展现出的成熟自托管记账产品风格：**冷静、清晰、轻量、信息密度适中、组件统一、手机端完整可用**。

目标不是简单换色，而是统一重做：
- 全局应用壳层与导航；
- 页面标题、内容宽度、卡片、统计摘要、列表与图表布局；
- 按钮、表单、下拉框、日期/月选择器、标签、提示、弹窗/底部弹层；
- 手机抽屉导航、底部主导航、悬浮新增入口、安全区与软键盘适配；
- 浅色 / 深色双主题；
- loading、empty、error、permission、offline、syncing、conflict 等完整状态。

**视觉参考不覆盖业务设计**：不得照搬 HomeLedger 的账本逻辑、页面字段、数据结构或业务规则。不得为了贴近参考样式而删减 FastLadger 已确认功能。

## 2. 参考项目拆解与迁移映射

| 参考项目表现 | FastLadger 采用方式 | 不直接照搬的部分 |
|---|---|---|
| 冷灰背景、白色内容卡片、蓝色主色 | 采用冷灰中性色 + 蓝色主操作色，建立 CSS 变量/设计令牌 | 不复制对方 CSS 文件或逐条样式实现 |
| 侧边栏分组导航 + 顶部工具栏 | 桌面端采用**吸顶顶栏 + 5 项顶部主导航 + 账本切换置顶栏**（D-3）、统一内容区；**左侧栏为可选替代形态，需 Owner 书面修订 D-3 后方可启用** | 导航项目按 FastLadger 既定页面和 D-3 编排；不引入侧栏主导航 |
| 手机汉堡抽屉 + 底部导航 + 中央新增按钮 | 手机端采用**抽屉承载全量低频导航**；底栏**严格 4 项**（首页/记一笔/报表/我的，D-3），「记一笔」可视觉突出但**不新增第 5 槽** | 具体 Tab 数和顺序遵守 FastLadger 已定 D-3，不照搬对方 5 项 |
| 统计摘要卡片、图表卡片、最近交易列表 | 首页优先呈现关键财务摘要、趋势、最近交易和快捷操作 | 指标定义严格遵循 FastLadger 会计口径，不能照搬对方计算 |
| 自定义下拉、日期/月选择器、确认弹窗 | 统一控件视觉（高度/边框/焦点环），**原生控件在可访问性更优时允许保留** | 控件字段与可操作性以 FastLadger 需求/API 为准；不得为外观统一牺牲键盘/读屏/本地化 |
| 触控目标加大、筛选横向滚动、移动端底部弹层 | 采用移动优先布局与触控交互，所有页面检查横向溢出 | 断点和设备检测按 FastLadger 浏览器支持矩阵验收 |
| 浅色/深色主题 | 两套主题共享语义令牌，所有图表/图标/控件同步适配 | 不允许仅背景变暗、文字和图表仍使用浅色硬编码 |
| Lucide 线性图标体系 | **应用自身**的导航/按钮/操作/状态图标统一为 Lucide 线性风格，尺寸/笔画一致 | 业务分类可保留用户自定义图标；用户备注/商户等业务数据不替换 |

## 4. 应用壳层与导航

### 4.1 桌面端（**以 D-3 为准：5 项顶部主导航 + 账本切换置顶栏**）

> **D-3 原文**（`docs/FastLedger-R0-收尾执行清单.md` L115）："移动端 4 Tab：首页 / 记一笔 / 报表 / 我的；**桌面端 5 项顶部导航**；账本切换置于顶栏。"
> 本节曾写作"左侧主导航固定 232px"，与 D-3 冲突；**UI-DESIGN-01-R1 依第三方复核 UIREV-01 修订**，改为以下口径。

- **主导航形态：顶部水平导航，恰为 5 项。** 品牌区在左，5 项主导航居中/紧随品牌，**账本切换与用户/设置入口在右侧**，层级清晰。
- **账本切换置顶栏**（D-3），不进入 5 项主导航计数，不得单独占一项主导航。
- **不得出现第 6 个主导航项**。超出 5 项的页面（账本列表、分类管理、预算、投资资产、导出、对账/账户、成员、回收站、设置）一律进入"更多"菜单或在「我的」页分组呈现。
- **左侧栏为非默认方案**：`--fl-sidebar-width` 仅在 Owner **书面修订 D-3** 并同步权威决策文档后启用；本规范不以此为实现要求，实施方不得自行改为侧栏。
- 顶部工具栏吸顶，含页面标题/副标题、主操作；可选搜索与通知。不重复堆叠页面内已有的主操作。
- 主内容区必须设置合理最大宽度与留白，避免表格/卡片贴边或无限拉伸。
- 导航 active 状态使用主色浅底 + 主色图标/文字；hover、focus、disabled 状态统一；键盘 Tab 可遍历、焦点可见。
- 页面滚动区域明确，避免顶栏与主内容互相抢滚动。
- **验收**：`nav` 内主导航项 DOM 计数 == 5；账本切换位于顶栏；无第 6 项；无侧栏主导航。

### 4.2 手机端

- **底部导航严格 4 项**：首页 / 记一笔 / 报表 / 我的（D-3 原文）。
- **「记一笔」是 4 项之一**，可作视觉突出（放大、主色、凸起），**不得因此新增第 5 个槽位**。若保留悬浮按钮外观，它必须与"记一笔"这一 Tab 为**同一目的地**（同一 `aria-label`、同一动作），在 DOM 与可访问性树中不构成独立第 5 入口，也不得并存两条独立记账路径。
- **交易总表固定放在「我的」下**作为辅助检索入口（D-6），**不得回到底栏主导航**；底栏不得出现「账单」Tab。
- 汉堡抽屉承载**全量低频页面**（账本管理、数据、预算与资产、设置/登出），不挤入底栏；遮罩层可关闭，抽屉打开时锁定背景滚动，支持 Escape/返回关闭。
- 底部导航、抽屉、底部弹层均使用 `env(safe-area-inset-*)` 处理刘海与 Home Indicator。
- 输入时考虑软键盘遮挡；主要提交按钮不能被键盘/底栏遮住。
- 手机端筛选 chips 可横向滚动但需有明确溢出提示/可操作性；页面本身不得出现意外横向滚动。

### 4.3 FastLadger 导航映射约束

导航必须遵守已裁决的 D-3（移动端 4 Tab、桌面端 5 项顶部导航）以及 D-6（交易总表保留为“我的”下辅助入口）等既定决策。HomeLedger 的导航仅作为信息分组参考，不构成修改 FastLadger 导航数量、顺序或入口归属的授权。

## 5. 页面模板

### 5.1 首页 / 总览

- 首屏先给出核心财务摘要卡片，最多突出 3–4 个核心指标；每张卡片包含清晰标题、主要金额、必要的辅助说明/比较值。
- 主内容采用响应式双栏/单栏：主要区域呈现收支趋势、最近交易；次要区域呈现今日速览、预算/提醒等。
- 图表卡片有标题、统计区间、图例/单位、空状态；移动端图表不得压缩到无法读数。
- 首页快捷新增操作易触达，但不与底部中央主操作重复制造多个强主按钮。
- 指标必须遵守 FastLadger 会计定义：净资产 = 资产 − 负债；负债不得作为正资产相加；持仓是否计入必须按权威数据和口径明确。

### 5.2 交易列表 / 交易详情

- 交易以日期分组，金额右对齐；收入/支出/转账等类型使用语义色、符号和类型标签共同表达。
- 每行明确展示分类、账户、商家/对方、备注等最重要信息；次要字段按断点收纳，不可因字段过多造成重叠。
- 点击行进入完整详情或打开符合平台习惯的详情弹层；编辑、删除、恢复等操作有明确权限和确认反馈。
- 筛选区分主要筛选与高级筛选；手机端高级条件收纳到抽屉/底部弹层，已选条件以 chips 显示。
- 批量操作必须有选中数量、操作对象、危险操作确认与结果反馈。

### 5.3 账户 / 资产

- 净资产、总资产、总负债以清晰摘要卡片展示，账户按资产/负债/投资等类别分组。
- 账户行突出名称与当前余额；币种、账户类型、尾号等作为辅助信息。
- 余额颜色不能单独决定资产/负债性质；需同时显示账户类型或负债标签。
- 账户详情、持仓与资金账户关系按 FastLadger 既定业务模型呈现，不照搬参考项目的账户结构。

### 5.4 报表 / 分析

- 页面顶部统一时间范围/统计对象控件；摘要指标、趋势、分类构成、排行按信息层级分卡片。
- 图表颜色从主题令牌读取，图例、tooltip、坐标轴、空态和错误态均支持浅/深色。
- 移动端图表优先纵向堆叠，避免小屏双栏；数据表格允许横向滚动容器，但不能让整个页面溢出。

### 5.5 表单 / 记一笔

- 表单分组卡片化，主金额输入优先级最高；交易类型切换明显，金额、日期、账户、分类等核心字段顺序稳定。
- 手机端单列；提交/取消按钮在底部易触达且避开安全区/软键盘。
- 高级字段可折叠，但折叠前应有明确提示；必填、错误、禁用和帮助文本样式统一。
- 分类选择使用网格/分组选择器，当前选择状态明显；不能为了美观隐藏关键字段。

## 6. 通用组件规范

- **卡片**：白/深色表面、细边框、14px 圆角；标题区统一对齐，操作入口放标题右侧。
- **按钮**：Primary / Secondary / Ghost / Danger 四种语义；高度、图标、文字间距统一；加载时防重复提交。
- **表单控件**：统一高度、边框、focus ring、placeholder、disabled、error 状态；手机触控目标至少 44px。**原生 `<select>` / `<input type="date">` 在可访问性更优时允许保留**（判据见 §6.1）。
- **下拉选择**：需要图标列、副文本、长文本省略、分组吸顶、视口边缘自适应时使用项目自定义选择器；**若改用自定义，必须同时具备键盘方向键选择、`role="listbox"`、`aria-activedescendant`、焦点可见与触控 ≥44px**。仅外观差异不构成替换理由（判据见 §6.1）。
- **日期/月选择器**：视觉与下拉统一，支持当前值直达、前后切换、清除/今天等适用快捷操作；移动端遵循系统触控习惯。
- **弹窗/底部弹层**：桌面居中 Dialog；手机优先 Bottom Sheet，支持拖拽/按钮关闭、遮罩、焦点管理、Escape；危险动作需明确文案。
- **提示与状态**：Success / Info / Warning / Error 样式统一；不能只靠 toast 告知必须处理的错误。
- **图标**：统一 Lucide 线性风格，常规 18px、小图标 15px、大图标 22px；同一功能全站使用同一图标。**替换范围仅限应用自身的装饰性/功能性图标**（导航、按钮、行操作、状态、空状态、占位）；**用户自定义分类图标、备注/商户/账本名等业务数据，以及后端返回的名称文本，一律不得批量替换**。验收以"图标来源清单逐项替换"为准，不以全仓 emoji 数量为零为准。
- **动效**：轻量 120–180ms，尊重 `prefers-reduced-motion`；不得用动画掩盖加载延迟或状态不明确。

### 6.1 原生控件保留判据（不追求"数量归零"）

自定义控件**不天然优于原生控件**。是否替换按场景逐个决策，判据如下：

**可以替换为自定义控件的条件（四项全部满足）**：
1. 原生控件确实无法表达需求（如需图标列、父子分组、长文本省略、多选、范围选择）。
2. 已实现键盘完整可达：Tab 进出、方向键移动、Enter/Space 选中、Escape 关闭，焦点可见。
3. 已实现读屏可达：`role="listbox"/"option"`、`aria-activedescendant`、可读名称、状态播报。
4. 移动端触控 ≥44×44px，弹层不被软键盘或安全区遮挡。

**应当保留原生控件的场景**：
- 选项较多且依赖首字母跳转的筛选（类型/账户/分类筛选）。
- 日期输入：原生 `input[type=date]` 自带本地化、日历键盘操作与读屏支持，自研难以等价。
- 选项少、无层级、无图标需求的下拉（预算类型、投资类型、账户类型）。
- 分页、条数等无控件语义的操作用按钮即可。

**验收方式**：不验收"标签数量归零"，验收"交互一致且可访问"——每个被替换的控件提交键盘/读屏/焦点/触控/本地化五项证据；每个保留原生的控件在清单中记录保留原因，并验证与主题的视觉协调（统一高度、边框、焦点环，必要时用 `appearance` 与包装层统一，但不替换语义）。

## 7. 状态设计（每页强制覆盖）

每个数据页面至少定义并验收：
1. Loading：骨架/加载提示，完成或失败后必须清除。
2. Empty：解释为什么为空，并给出有权限的下一步入口。
3. Error：请求失败有可见错误、重试路径，不得只留空白/永久骨架。
4. Permission：无权限时隐藏或禁用写入口，并说明原因；UI 不替代后端鉴权。
5. Offline：标明当前离线、数据缓存范围和最后同步时间。
6. Syncing / Pending：区分本机待同步与服务端已确认，不得把 pending 显示成已入账。
7. Conflict：展示冲突原因和允许的处理方式，不能静默丢弃。
8. Success：创建/更新/删除/恢复后有真实结果反馈，并确保列表与摘要同步刷新。

## 8. 响应式与可访问性验收

- 至少覆盖 390×844、430×932、768×1024、1024×768、1440×900 五类视口；同时覆盖触屏宽视口设备。
- 手机布局不能只用桌面缩窄实现；侧栏、导航、表单、表格、图表按手机场景重新排布。
- 所有页面无非预期横向溢出；表格确需横向滚动时，仅滚动表格容器。
- 交互控件最小触控区域 44×44px；键盘可达、焦点可见、Dialog 焦点不逃逸。
- 文本与背景对比度、状态颜色、图表颜色需兼容浅/深主题。
- 必须在真实 Android Chrome 与 iOS Safari 测试；桌面缩放模拟不能代替真机。
- 每个页面至少提交桌面 + 手机截图；核心流程提供操作录屏或自动化证据；所有截图使用同一组确定性数据。

## 9. 实施顺序与禁止事项

建议实施顺序（对应《开发WBS》附录 B 的 UI-DESIGN-02~08）：

| 步骤 | 任务 | 内容 | 代码门禁 |
|---|---|---|---|
| 0 | UI-DESIGN-01 | 页面/组件盘点、差异矩阵、任务拆分 | 纯文档，可做 |

**02a 与 02b 的边界（重要）**：02a 的产出物是**文档**（Markdown 表格与说明），**没有**任何 `server/web/dist/` 下的文件改动。不得以"只需改几行 CSS 变量""先试点一个令牌"等理由提前进入运行时改造——任何 `style.css` / `index.html` / `app.js` 的改动都属于 02b，须等门禁放行。若未来获准改 CSS，须**先冻结 R0 所需基线截图、SHA 与测试证据**，并明确该次 UI 改造与 R0 验收证据的隔离策略，不得覆盖或替换既有证据。

禁止：
- 只换主色/圆角，不调整信息架构和页面布局，却宣称完成设计迁移。
- 复制 HomeLedger 的整份 CSS/JS/EJS、品牌图标、文案或业务代码；应提炼设计原则并用 FastLadger 自己的组件和语义重新实现。
- 擅自改变 PRD、业务流程、会计口径、API、数据库、权限、同步/离线契约。
- 在 R0 未通过前启动 R1–R7 / PWA 业务实施；本规范可以先完成文档设计、任务拆分和评审，不构成跳过 R0 的授权。
- 把 UI-DESIGN-02a 解释为"可提前修改 CSS/HTML/JS"的授权。
- 以侧栏替代 D-3 规定的 5 项顶部主导航；在手机底栏新增第 5 个主导航项；把交易总表放回底栏（违反 D-6）。
- 为统一外观而批量替换用户自定义分类图标、备注/商户文本等业务数据。
- 以"原生控件数量归零"作为验收目标，或以自定义控件替代可访问性更优的原生控件。
- 用截图相似度替代真实交互、权限、状态、数据正确性验收。
- 把“桌面浏览器缩窄”当作手机真机验收。
