## 附录 A：§12.1 剩余 3 项待确认的建议方案（待 owner 裁决）

> 以下建议稿**已由 owner 于 [1.12] 全部裁决采纳**，对应内容已转入 PRD §12.1 为【决策】；本附录保留为设计说明，与 PRD 冲突时以 PRD 为准。

### 提案 1：权限变化与本地缓存重建

**问题**：互看从开变关、成员被移除/重新加入时，离线缓存、已同步版本与新可见范围如何重建；历史已看/已导出数据服务端无法收回。

**建议**：

1. **服务端权威**：可见性判定只在服务端执行（PRD §7.3 已定），客户端不自行过滤。
2. **事件枚举**：把触发重建的事件收敛为四类——`visibility_changed` / `member_removed` / `member_role_changed` / `book_deleted`，经 WS 广播；广播内容**脱敏**（仅 `book_id` + 事件类型 + 版本），关闭互看时不带金额/账户/备注。
3. **定向重拉而非清库**：客户端收到事件后对该账本执行定向重建——丢弃本地缓存中当前用户无权访问的记录，并以 `afterVersion=0` **全量重拉该账本**（可见范围变化后增量语义不可靠）。不要清空整个本地库（会丢失其他账本数据）。
4. **版本号处理**：可见性变化**不递增业务 `sync_version`**（它不是数据变更），改用事件携带 `force_full_resync=true` 触发重拉，避免污染版本号语义。
5. **被移除成员**：收到 `member_removed` 后客户端**主动清除该账本全部本地数据**并停止订阅——这是最符合隐私预期的行为。
6. **隐私边界必须明说**（诚实声明，写进 PRD §7.3 与设置页文案）："关闭互看仅对未来同步生效；成员此前已查看或已导出的数据，服务端无法收回。" 建议该提示常驻显示于可见性开关旁。

**影响阶段**：3.4（可见性 + 缓存重建）。

### 提案 2：实例管理员与账本 owner 边界

**问题**：谁可下载整库备份、修改 LLM 密钥；普通账本 owner 不等于实例管理员，不默认获得所有私账。

**建议**：

1. **两层角色正交**：引入**实例管理员**（instance admin）与**账本角色**（owner / admin / member），二者严格分离，不互相推导。
2. **实例管理员**（首个创建的用户默认获得，可后续转移/移除）：
   - 可：下载整库备份、修改全局配置（LLM 密钥、`EBK_ENABLE_REGISTER`）、查看实例级日志、启停备份任务。
   - **不可**：默认读取任意私账明细。
3. **账本 owner**：仅限本账本内的管理（成员、分类、账户、设置、可见性），**不等于实例管理员**，不自动获得其他账本/私账访问权。
4. **整库备份的越权风险**（关键）：整库备份必然包含所有私账，因此
   - 整库备份下载**仅限实例管理员**，且文件权限受控（600）、下载动作写审计；
   - 对普通 owner 改为提供**"按账本导出"**（仅导出其有权访问的账本），从机制上避免 owner 借整库备份越权查看他人私账。
5. **LLM 密钥修改**：仅实例管理员；修改后写 `audit_logs(action=config_change)`。
6. **数据模型**：`users` 增 `is_instance_admin` 布尔（或独立 `instance_admins` 表），与 `book_members.role` 严格分离。默认首个 owner 自动成为实例管理员（方便家庭自用），但可在设置中转移。

**影响阶段**：1.4（权限矩阵）、1.6（实例管理员位）、7.2（备份下载权限）。

### 提案 3：关闭公开注册后的成员入户

**问题**：`EBK_ENABLE_REGISTER=false` 时，邀请链接是否可注册、邀请码有效期 / 单次使用 / 角色绑定 / 限流如何定义。

**建议**：

1. **邀请与公开注册解耦**：`EBK_ENABLE_REGISTER=false` 只关闭"任何人可自助注册"，**不影响邀请码注册**；邀请是关闭注册后的唯一入户通道。
2. **邀请码属性**：由 owner / admin 生成（权限矩阵：邀请/移除成员 owner✅ admin✅），绑定
   - **账本 ID + 角色**（member / admin）
   - **有效期**：默认 7 天（可配 `EBK_INVITE_TTL_DAYS`），到期自动失效
   - **单次使用**：用后标记 `used_at` / `used_by`，不可重复使用
   - **可选绑定**邮箱或用户名：若绑定则校验一致才可注册，防止链接转发滥用
3. **限流**：每账本每分钟生成上限（建议 5）、同一 IP 每小时尝试上限（建议 10）；失败计入审计。
4. **注册流程**：访问邀请链接 → 展示账本名与邀请人 → 设置用户名/密码 → **原子**（同事务）建 `user` + 建 `book_members`，并按邀请码绑定角色入账本。
5. **全生命周期审计**：生成 / 使用 / 撤销 / 过期均写 `audit_logs`；owner 可手动撤销未使用的邀请。
6. **极端情况**：实例无任何用户（首次启动）走 owner 初始化（CLI / 首启向导），不受邀请流程限制。

**影响阶段**：1.5（邀请码入户）。
