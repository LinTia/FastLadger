### UI01-RV-04 — P1：首页“结余”与“净资产”口径被混为一谈

**证据**
- PRD `docs/FastLedger-产品需求文档-PRD.md` §4.2 L192–198：首页要求展示“本月支出、本月收入、结余”。
- 当前 `server/web/dist/app.js` L1983–1997：收入/支出来自月报；第三张卡显示主标签“结余”，其辅助文案是“净资产”，数值却是所有账户 `balance` 求和。
- 投资页的权威净资产来自 `GET /books/:id/net-worth`；路由见 `server/internal/api/router.go` L230，服务计算见 `server/internal/service/invest.go` L534–590，公式为资产账户 + 持仓市值 − 负债账户。

**问题**
报告写成“首页和投资页都叫净资产”，不够准确：首页主标签是“结余”，只是副文案“净资产”造成语义混淆。更重要的是，PRD 首页的“结余”不等同于投资页的“净资产”。不能直接把首页改为调用 net-worth 接口。

**建议**
- 首页“结余”按 PRD 的月度收支语境定义，建议为“本月收入 − 本月支出”；
- 投资页继续展示资产负债口径的“净资产”；
- 删除首页卡片“结余”下方误导性的“净资产”副文案，或改成能准确描述月度结余的说明；
- 若 Owner 希望首页同时展示家庭净资产，应作为独立指标另行提出，不得替换“结余”。

**待 Owner 确认**
仅确认首页“结余”公式是否采用本月收入减本月支出。报告中的“首页改用 GET /net-worth”建议应撤回。

## 3. 需要修正的事实 / 证据质量问题

### UI01-RV-06 — P2：PR #3 基线差异描述范围过宽

报告 L7 写“PR #3 分支与 origin/main 的差异仅在 `server/web/dist/app.js`”。实际核对结果：
- 在 Web runtime 文件中，`index.html` 与 `style.css` 的 SHA 与 main 相同，`app.js` 不同；
- 但整个 Git 分支还包含 workflow、R0 证据、测试脚本、报告等多项差异，且相对 main 已发生分叉。
- 建议改为：“**在 `server/web/dist/` 三个运行时文件中，仅 `app.js` 与 main 不同；整个 PR #3 分支并非只改一个文件。**”

### UI01-RV-07 — P2：导出预设“初始全部 active”不是已证明的可见缺陷

报告 L281（对应原报告 §3.15）指出四个预设按钮初始都赋予 `active`。但 `app.js` L1005 在 `view.append(card)`（L1081）之前同步调用 `setRange("this")`，会在页面绘制前把 active 收敛到“本月”一个按钮。当前静态代码不足以证明用户实际看到四个按钮同时高亮。
- 删除该 finding，或提供真实浏览器截图/录屏证明错误状态在绘制时可见。

### UI01-RV-08 — P2：net-worth API 路径不完整

报告多处写 `GET /net-worth`。真实路由是 `GET /books/:id/net-worth`（`server/internal/api/router.go` L230）。请在报告、差异矩阵、任务单中使用完整路径，并标注 bookId 作用域。

### UI01-RV-09 — P2：组件验收条件过度绝对化

报告 UI-DESIGN-03 要求全站原生 `<select>` / `<input type=date>` 数量归零，以及 22+4 种 emoji 全部归零。这超过视觉规范原文：
- 规范要求“优先项目自定义选择器”，并未禁止所有原生控件；
- 原生日期/选择控件可能提供更好的系统键盘、屏幕阅读器与移动端交互，需逐项评估；
- 规范明确允许用户自定义分类图标，不能把用户数据中的 emoji 当作装饰图标全部替换。
应改成“按控件逐项评估；自定义控件必须通过键盘/屏幕阅读器/触控验收；保留合理的原生控件和用户自定义图标”。

### UI01-RV-10 — P2：D-3 / D-6 已定事项不应继续列为待裁决

- 报告 §4 冲突 1 的移动端导航结构已由 D-3 + D-6 定稿；
- 报告 §4 冲突 2 的桌面 5 项顶部导航已由 D-3 定稿；
- 这两项应改为“必须遵守的实施约束”，不是 Owner 再次确认。
- 冲突 5 的手机端设置/登出不可达属于既有功能缺陷，修复目标已明确；入口具体放“我的”还是次级菜单可在不改变 D-3/D-6 的前提下给出设计建议，不应把“是否修复”作为待决。
- 分类管理 API 是账本作用域 `/books/:id/categories`，其归属应按账本级功能设计，不应把它作为用户个人偏好功能。
